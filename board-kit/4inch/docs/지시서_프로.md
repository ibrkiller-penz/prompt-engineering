# 프로용 작업지시서(토큰 적게): 교실 알림판 4인치

**원칙**: 되풀이되는 일(설치 확인 · 샘플 자료 · Firebase 올리기 · 내 값 넣기 · 빌드 · 굽기)은 **스크립트 하나**가 한다.
AI는 ① 스크립트가 멈췄을 때 **오류 몇 줄**을 보고 고치거나 ② 사용자가 원하는 **작은 수정**만 한다.
더 자세한 사실이 필요하면 `docs/지시서_맥스.md` 의 해당 장만 골라 읽는다(2장 하드웨어 · 4장 빌드 · 5장 화면 · 8장 코드 안내).

## 1. 사용자가 직접 하는 순서 (AI 없이)

1. 키트를 **영문 폴더**에 푼다. 예: `C:\dev\board-kit` (한글·빈칸 폴더는 빌드가 멈출 수 있다)
2. 보드의 **USB-C 단자**에 데이터 케이블로 꽂는다(4인치는 단자 하나로 굽기·기록을 다 한다).
3. PowerShell 을 열고 한 줄 실행:
   ```
   powershell -ExecutionPolicy Bypass -File C:\dev\board-kit\4inch\tools\quick_start.ps1
   ```
   스크립트가 차례로 묻고 진행한다: 프로그램 확인 → 샘플 자료 → Firebase 올리기(**로그인은 직접**) → 내 값(학교 코드·위치) → 빌드(처음 35~45분) → 보드 찾기 → 굽기.
   이미 끝난 단계는 건너뛴다. 여러 번 돌려도 된다.
4. 보드 화면 **⑤ 설정 → 찾기** 에서 와이파이를 고르고 비밀번호를 직접 넣는다.
5. 멈추면 화면의 **빨간 줄(X 줄) 몇 개만** AI에게 붙여 넣고 "고쳐 줘"라고 한다.

## 2. AI가 할 일 (프로)

- 사용자가 붙여 넣은 오류 줄로 판단한다. 필요한 파일만 찾아서 연다(통째로 읽지 않기).
- 한 번에 고치고 **한 번** 빌드·확인한다. 보고는 3줄 이내.
- 단계마다 되묻지 않는다. 사용자가 정해야 하는 것(값·허락)만 묻는다.
- 고칠 곳이 **화면 설정(떨림·밀림)** 이면 손대지 말고 "맥스용으로 바꿔서 하자"고 말한다.

## 3. 자주 하는 작은 일

| 하고 싶은 일 | 하는 법 |
|---|---|
| 내 값(사이트 주소·학교 코드·위치·수능 날짜) 바꾸기 | `quick_start.ps1` 다시 실행, 또는 `firmware/include/board_config.local.h` 고치고 `build_board.ps1 -Port COM번호` |
| 교시 시작 시각 | `board_config.h` 의 `BOARD_PERIOD_START` (점심 "12:30"·"13:30" 은 `main.cpp` 에서) |
| 내 시간표 올리기 | `../common/tools/data-format.md` 모양으로 `../common/site/public/board/` 에 넣고 `firebase deploy --only hosting` |

## 4. 자주 막히는 곳 (짧게)

| 증상 | 해결 |
|---|---|
| 빌드가 `CMake Error` | 키트를 영문 폴더로 옮기고 `build_board.ps1` 로 빌드 |
| 보드를 못 찾음 | 데이터 케이블 · 다른 USB 구멍. 그래도 안 되면 BOOT 단추를 누른 채 USB 를 꽂고 다시 |
| 화면이 깜깜 | 밝기 255(꺼짐)일 수 있음 → USB 를 완전히 뽑았다 꽂기 |
| 부저가 계속 울림 | USB 를 뽑고 10초 뒤 다시 꽂기 |
| 화면이 떨리거나 밀림 | 와이파이 받는 20~30초 동안은 정상. 계속되면 맥스용으로 |
| 글자 없이 색 띠만 | `lv_conf.h` 의 `LV_USE_FONT_COMPRESSED` 가 1 인지 |
