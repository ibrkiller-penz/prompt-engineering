# 인공지능 수학 꼭지 — 콘텐츠 형식과 작성 규칙

사이트 안의 새 꼭지(`/aimath`)에 들어가는 **단원별 학습 자료**를 쓰는 규칙이다. 내용은 JSON 파일이고, 화면은 이 파일을 읽어서 그린다. 형식 정의는 `src/aimath/types.ts` 가 기준이다.

## 0. 가장 중요한 규칙: 저작권
- 참고 자료(비상교육 교과서·지도서·비바샘 자료, 작업 폴더의 `aim/` 아래 글자 파일)는 **무엇을, 어떤 순서로 배우는지(범위·용어·개념)를 파악하는 용도**로만 읽는다.
- **문장·문제·예시 자료·그림 설명을 그대로 옮기지 않는다.** 모든 설명은 **내 말로 새로 쓰고**, 예시와 문제는 **새로 만든다**(숫자·상황·단어를 바꾼다). 교과서의 예제를 숫자만 바꿔 베끼는 것도 안 된다. 개념 자체(정의, 공식, 알고리즘)는 누구의 것도 아니므로 정확하게 쓴다.
- 교과서의 쪽수, 삽화, 구성 이름(‘개념 탐구’ 같은 상표성 이름)은 쓰지 않는다. 실제 인물·역사적 사건을 쓸 때는 **확실히 아는 사실만** 쓴다(이름·연도·업적). 확신이 없으면 연도를 빼거나 쓰지 않는다. 틀린 사실을 쓰는 것이 빈약한 것보다 나쁘다.
- 참고 자료 파일을 저장소(`content/`)에 복사하지 않는다.

## 1. 파일 위치
```
content/aimath/units.json                 단원 목록(이미 있음, 고치지 않는다)
content/aimath/u1/unit.json               대단원 내용: why / opening / test / future   (UnitContent)
content/aimath/u1/lesson-1.json           중단원 레슨 (Lesson)  — 파일 이름은 lesson-<번호>.json
content/aimath/u2/..., u3/..., u4/..., u5/...
```
레슨 `id` 는 `units.json` 의 것과 같게(`u2-1`). 문제 `id` 는 레슨 안에서 겹치지 않게 `레슨id-번호`(예: `u2-1-q07`). 대단원 종합은 `u2-t01` 형식.

## 2. 글자 서식 (Text)
- `**굵게**`, `$수식$`(KaTeX), 줄바꿈 `\n`. **HTML 태그는 쓰지 않는다.**
- **JSON 파일은 반드시 Write 도구로 만든다. 셸(echo, cat 과 heredoc)로 만들면 역슬래시가 줄어들어 수식이 깨진다.** 검사기는 `	imes` 가 탭으로 바뀐 것 같은 흔적도 오류로 잡는다.
- JSON 안의 역슬래시는 두 번: `"$\\frac{a}{b}$"`, `"$\\vec{x}\\cdot\\vec{y}$"`.
- 긴 식은 폰 화면에서 잘리므로 `{ "t": "math", "tex": ["식1", "= 식2"] }` 처럼 줄을 나눈다.
- 한 문단은 2~4문장. 문장은 짧게. 한자어·영어 용어는 처음 나올 때 쉬운 말로 풀어 준다.

## 3. 레슨(Lesson) 구성과 분량 (이 분량 이상으로, 얇게 쓰지 않는다)
| 필드 | 내용 | 분량 |
|---|---|---|
| `story` | **이야기.** 등장인물이 어떤 상황에서 문제를 만나고 궁금해하는지. 대화를 넣는다 | 문단 6~8개, 전체 1,000~1,500자 |
| `question` | 오늘의 핵심 질문 한 문장 | 1 |
| `sections` | **개념 정리.** 섹션 3~5개. 각 섹션에 `p`, `math`, `term`, `callout`, `table`, `list`, `example`, `dialog`, `widget` 블록을 섞는다 | 전체 3,000~5,000자, `example`(풀이 있는 예제) 3개 이상 |
| `terms` | 용어 카드 | 8~14개 |
| `aiStory` | **AI 이야기.** 역사·인물·실제 활용을 읽을거리로 | 문단 3~5개 |
| `practice` | **계단식 연습 문제** | 18~24문제 |
| `project` | **AI 프로젝트**(손으로/스프레드시트·종이로 해 보는 활동. 코딩 없이도 가능하게) | 단계 5~8개, `think` 3개 |
| `summary` | 오늘 배운 것 요약 | 5~7줄 |

### 이야기 쓰는 법 (`story`, `unit.opening`)
- 무대: 새봄고등학교 **AI랩** 동아리. 등장인물(모든 레슨에서 같은 사람):
  - **서하**(2학년, 부장, 질문 대마왕, 늘 “왜?”부터 묻는다), **도윤**(코딩 담당, 말수가 적지만 결정적인 한마디를 한다),
  - **하은**(미술·디자인 담당, 글과 그림의 ‘느낌’에 민감하다), **지후**(농구부 겸임, 기록과 숫자를 좋아하는 데이터 덕후),
  - **유 선생님**(수학 교사이자 동아리 지도 교사, 비유의 달인, 정답을 바로 알려 주지 않고 되묻는다),
  - **비트**(동아리 컴퓨터에 설치된 AI 도우미. 말투는 장난기 있고 친절하지만 **가끔 틀린다.** “AI도 틀릴 수 있다”는 장면을 자연스럽게 넣는다).
- 한 이야기에는 **구체적인 장면(시간·장소·소품)** 과 **대화**와 **작은 반전이나 웃음**이 있어야 한다. “오늘은 ○○을 배웁니다”식 설명으로 시작하지 않는다.
- 이야기는 그 레슨의 **수학 개념이 꼭 필요해지는 순간**에서 끝나고, `question` 이 그 질문을 받는다.
- 학교·실명·실존 기업/상표 비방, 정치·종교 소재는 쓰지 않는다. 폭력·혐오 표현 금지. 청소년이 읽는다.

### 개념 정리 쓰는 법 (`sections`)
- 순서는 **궁금증 → 직관(그림 같은 설명·비유) → 정의 → 계산 예제 → 흔한 실수 → AI에서 어디에 쓰이나.**
- 계산이 있는 개념은 반드시 **작은 숫자로 손으로 끝까지 따라가는 `example`** 을 넣는다(풀이는 `steps` 한 줄씩, `answer` 는 한 줄).
- `callout`: `tip`(요령), `warn`(흔한 실수), `aha`(아하! 연결), `try`(직접 해 보기). 섹션마다 1개 이상.
- `widget` 은 `types.ts` 의 `WidgetId` 중 **그 레슨에 맞는 것만**, 개념을 설명한 **뒤에** 둔다(체험 도구가 따로 만들어진다).

### 문제 쓰는 법 (`practice`, `unit.test`)
- 종류: `choice`(보기 4~5개, `answer` 는 보기 번호 0부터), `number`(숫자 답, 소수는 `tolerance`), `ox`, `open`(서술형: `model` 모범답안, `rubric` 채점 기준 2~4개).
- **계단식**: `level` 1(개념 확인)→5(심화). 연습 문제는 `group` 으로 묶어 **개념 확인 → 유형별(각 3~4문제) → 실력 UP → 도전** 순서로 둔다. 바로 앞 문제보다 **딱 한 가지만** 새롭게, 그 한 가지를 `new` 에 적는다.
- `hints` 는 정확히 2개(1번은 방향만, 2번은 거의 답 직전). `solution` 은 **왜 그런지**까지 쓴다. 오답 보기가 왜 틀렸는지도 필요하면 쓴다.
- 보기의 순서는 화면에서 섞이므로 정답을 어느 위치에 써도 된다. ‘모두 맞다/없다’ 같은 보기는 쓰지 않는다.
- **모든 계산 문제는 직접 계산해서(가능하면 python 으로) 정답을 확인한다.** 답이 두 가지로 해석되는 문제는 쓰지 않는다.
- `unit.test` 는 15~20문제(2점·3점·4점 느낌으로 쉬운 것→어려운 것), 대단원의 모든 중단원을 고르게 다룬다. `open` 은 3개 이하.

## 4. 대단원(UnitContent)
- `why`: 이 단원을 왜 배우는지(문단 2~3개, 실생활 연결).
- `opening`: 대단원을 여는 이야기(문단 4~6개, AI랩 인물 등장).
- `test`: 대단원 마무리 종합 문제.
- `future`: ‘수학! 미래를 꿈꾸다’ — 이 단원의 수학이 쓰이는 **직업·진로 이야기**(문단 3~5개). 가공의 인물을 만들어도 되지만 실존 인물인 것처럼 쓰지 않는다.

## 5. 검사
`node scripts/check-aimath.mjs` 를 돌려 형식 오류가 0이 되게 한다. 이 검사가 통과해도 **수학적 정확성은 별도**이므로, 숫자가 나오는 문제는 반드시 직접 다시 계산한다.

## 개정 — 교과서 없이도 공부할 수 있게 (2026-10-08 오후)

이 사이트는 **교과서가 없어도 혼자 공부할 수 있어야** 한다. 교과서는 내용이 축약돼 있고 불친절하므로, 이 사이트는 더 친절하고 풍성해야 한다. 다른 출판사(비상교육·천재교육) 자료는 **범위와 문제 유형을 참고만** 하고, 글·예제·문제·그림 표현은 모두 새로 쓴다(숫자와 소재를 바꾼다). 본문에 출판사 이름을 쓰지 않는다.

### 새로 생긴 필드
- `Lesson.prereq` — "먼저 알고 가요": `{title, intro?, items:[{term, text}]}`. 중학교·고1 수학에서 이 레슨이 기대는 것(분수·비율, 좌표, 함수, 평균, 부등식 …)을 4~6장의 카드로 짧고 쉽게 복습한다. 각 카드는 말로 풀어 쓰고 숫자 예 하나를 곁들인다.
- `UnitContent.stories` — "시작하기 전에 읽는 이야기": `[{title, kicker?, paragraphs}]` 3~4편, 편당 문단 6~9개. 단원이 어디서 왔고(역사·사람), 어디에 쓰이는지(현실 사례), 무엇이 헷갈리는지(오해 바로잡기), 이게 없다면 세상이 어떨지(상상)를 이야기로 푼다. 사실이 불확실한 연도·인명은 쓰지 않거나 "전해져요/알려져 있어요"로 완화한다.
- 위젯 id 추가: `truth`(진리표), `flow`(순서도 따라가기), `vecops`(벡터 연산), `tangent`(평균변화율→접선).

### 친절하게 쓰는 법
1. 새 용어는 **처음 나올 때** 풀어 쓴다("함수 f(x)는 숫자를 넣으면 숫자가 나오는 기계예요").
2. 공식이 나오면 ① 왜 필요한지 ② 말로 먼저 ③ 식으로 ④ 숫자 예 순서로. 한 줄도 건너뛰지 않는다(식 변형은 한 단계씩).
3. 예제는 쉬운 것 → 어려운 것 순으로 6개 이상, 풀이는 모든 단계를 적는다.
4. 각 섹션 끝에 "한 줄 정리" callout(kind aha)을 둔다. 자주 하는 실수는 warn callout.
5. 어려운 말 대신 비유(저울, 지도, 계단, 레시피)를 쓰되 비유의 한계도 한 줄 적는다.
6. 이야기는 8~12문단, 대화 중심. 이야기의 사건이 개념의 필요를 만들어야 한다.
7. 문제 구성 목표(레슨당 36~45개): 개념 확인 → **기초력 UP**(유형별 계산 연습, 숫자만 바꾼 비슷한 문제 3~4개씩) → 쉬운 응용 → **실력 UP**(여러 단계) → 도전. `group` 에 '기초력 UP · 유형 이름', '실력 UP' 처럼 쓴다.
8. 대단원 `test` 끝에 **학력진단평가 A회·B회**(각 8문제: 객관식 6 + 단답 `number` 2, `group` 은 '학력진단평가 A회'/'B회', id 는 uN-dA01…, uN-dB01…)를 붙인다.
