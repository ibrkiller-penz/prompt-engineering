## 0. 한 줄 요약

학생이 **"AI의 첫 결과물은 끝이 아니라 출발점"**이라는 생각을 몸에 익히도록,
**부탁하기 → 되말하기 확인 → 점검·검증 → 선택 기록 → 마무리**의 흐름을 직접 눌러 보며 연습하는 웹사이트를 만든다.
초·중·고 학교급별로 같은 13차시 뼈대를 쓰되, 말의 수준과 예시·도구 이름을 다르게 보여 준다.

이 사이트의 '프롬프트 엔지니어링'은 **멋진 주문을 외우는 법이 아니다.** 원하는 것을 분명히 말하고, AI가 어떻게 알아들었는지 확인하고, 결과를 판단하고, 기록을 남기는 **대화 습관**을 가르친다.

## 1. Claude Code에게: 이 작업을 하는 방식 (교재 내용을 그대로 적용)

이 사이트가 가르치는 원칙을 이 프로젝트를 만들 때도 똑같이 지킨다.

1. **되말하기 먼저** — 코드를 쓰기 전에 이 지시서를 네가 어떻게 이해했는지 '작업 전 네 줄'(문제·기준·경계·완료 조건)로 먼저 정리해서 보여 줘. 정해지지 않은 건 짐작하지 말고 물어봐.
2. **요청한 범위만 먼저** — 각 단계(Phase)에서 정한 범위만 만든다. 더 넣으면 좋을 아이디어는 코드에 넣지 말고 `docs/추가제안.md`에 따로 적고, 각 제안이 작업 시간·복잡도에 주는 영향을 함께 쓴다.
3. **선택 기록** — 기술·구조상 중요한 선택은 `docs/DECISIONS.md`에 다섯 줄로 남긴다: ① 고른 것 ② 고른 이유(사실/제약/추론 표시) ③ 고르지 않은 대안 ④ 불확실한 점 ⑤ 재검토 조건.
4. **재시작 여섯 줄** — 작업을 멈출 때마다 `docs/PROGRESS.md` 맨 위에 갱신한다: ① 현재 목표 ② 끝낸 것 ③ 확정한 선택과 이유 ④ 남은 차이와 위험 ⑤ 미정 사항 ⑥ 다음 시작점.
5. **검증 대상 분리** — 교재에서 옮긴 문장·예시는 원문(PDF)과 대조한다. 확인 못 한 내용은 `TODO(검토)` 표시를 남기고 지어내지 않는다.

### 4-1. 차시별 '오늘의 한 문장' (원문 그대로 사용 — 프롬프트 카드의 핵심 데이터)

| 차시 | 초등 | 중학교 | 고등학교 |
|---|---|---|---|
| 1 | 만들기 전에, 내가 원하는 걸 어떻게 이해했는지 먼저 말해 줘. | 만들기 전에, 내가 원하는 것을 네가 어떻게 이해했는지 먼저 말해 줘. | 작업을 시작하기 전에, 네가 이해한 내 목표와 조건을 먼저 설명해 줘. 정하지 않은 건 짐작하지 말고 물어봐. |
| 2 | 네가 만든 것이 내가 원한 것과 어디가 같고 어디가 다른지 알려 줘. | 네가 만든 결과물이 내 조건(지역, 시간, 출처)을 어떻게 채웠는지 하나씩 짚어 줘. | 네 결과물이 내 평가 기준 각각을 어떻게 충족했는지, 근거와 함께 하나씩 짚어 줘. |
| 3 | 네가 생각한 내 목표를 먼저 말해 줘. 그다음에 맞는 것과 다른 것을 알려 줄게. | 네가 이해한 내 목표를 먼저 설명해 줘. 그다음에 내가 맞는 부분과 다른 부분을 알려 줄게. | 네가 이해한 내 목표를 먼저 설명해 줘. 맞는 부분과 어긋난 부분을 구분해서 알려 줄게. |
| 4 | 내가 부탁한 것만 먼저 만들어 줘. 다른 좋은 생각은 맨 아래에 따로 적어 줘. | 부탁한 범위 안에서만 먼저 만들어 줘. 더 넣으면 좋을 아이디어는 맨 아래에 '추가 제안'으로 따로 적어 줘. | 요청한 범위 안에서만 먼저 만들어 줘. 확장 아이디어는 맨 아래에 '추가 제안'으로 분리하고, 각각이 시간과 분량에 주는 영향도 알려 줘. |
| 5 | 방금 내가 말한 '짧게'를 너는 어떤 뜻으로 알아들었어? | 방금 내가 말한 '간단하게'를 너는 어떤 뜻으로 이해했어? | 방금 내가 말한 '고등학생 수준'을 너는 어떤 기준으로 이해했어? 판단할 수 있게 구체적으로 말해 줘. |
| 6 | 이 네 칸을 네가 어떻게 이해했는지 말해 줘. 모르는 건 짐작하지 말고 물어봐 줘. | 이 네 가지를 네가 어떻게 이해했는지 먼저 설명해 줘. 아직 정하지 않은 건 짐작하지 말고 물어봐 줘. | 이 네 가지를 네가 어떻게 이해했는지 먼저 설명해 줘. 정하지 않은 건 짐작하지 말고 물어봐. 전체 말고 목차부터 보여 줘. |
| 7 | 네 대답에서 내가 꼭 확인해야 할 날짜와 숫자를 알려 줘. | 네 답에서 내가 직접 확인해야 할 사실(날짜, 숫자, 출처)을 따로 표시해 줘. | 네 답에서 내가 1차 자료로 직접 확인해야 할 사실·수치·출처를 목록으로 분리해 줘. 네가 확실하지 않은 것은 표시해 줘. |
| 8 | 내 말을 잘못 알아들은 거야, 아니면 생각이 다른 거야? 다르면 이유를 알려 줘. | 내 뜻을 잘못 이해한 거야, 아니면 이해했지만 생각이 다른 거야? 다르다면 이유를 알려 줘. | 내 의미를 잘못 이해한 거야, 이해했지만 판단이 다른 거야? 판단이 다르다면 근거를 한 번 분명하게 말해 줘. |
| 9 | 다 된 것과 남은 문제를 나눠서 알려 줘. 끝낼지는 내가 정할게. | 채워진 조건, 남은 문제와 위험, 네 반대 의견을 나눠서 보여 줘. 끝낼지는 내가 처음 목표를 기준으로 정할게. | 충족된 조건, 남은 차이와 위험, 네 반대 의견을 나눠서 보여 줘. 종료 여부는 처음 제기한 문제를 기준으로 내가 판단할게. |
| 10 | 하나만 추천하고, 고른 이유와 빼 버린 것도 알려 줘. | 하나만 추천해 주고, 고른 이유와 뺀 후보, 아직 확실하지 않은 점을 나눠서 알려 줘. | 하나만 추천하고, 고른 근거와 뺀 대안, 아직 불확실한 점을 나눠서 알려 줘. 근거가 사실인지 추론인지도 표시해 줘. |
| 11 | 지난번에 정한 건 이거야. 지금도 맞는지 먼저 확인해 줘. | 지난번에 정한 기준은 아래와 같아. 지금도 이 기준이 맞는지 먼저 확인해 줘. | 지난 작업에서 정한 기준과 이유, 남은 위험은 아래와 같아. 지금도 유효한지 먼저 검토해 줘. |
| 12 | 다 된 것과 아쉬운 점을 정리해 줘. 이번엔 여기서 마무리할게. | 지금까지 채운 조건과 남은 아쉬움을 정리해 줘. 이번 단계는 여기서 마무리할게. | 지금까지 충족한 조건과 남은 한계, 재검토 조건을 정리해 줘. 이번 단계는 여기서 승인본으로 닫을게. |

> 위 표는 PDF에서 추출한 것이다. 줄바꿈 때문에 생긴 띄어쓰기 오류가 없는지 원문과 한 번 더 대조할 것.

## 5. 사이트 구조 (정보 구조)

```
/                         첫 화면: 학교급 고르기(초·중·고) + 사이트 한 줄 소개
/:level                   학교급 홈: 13차시 지도(1~7 확인 / 8~10 판단 / 11~13 기록·마무리), 이어서 하기
/:level/pledge            나의 AI 약속 / 협업 원칙 (체크 + 이름 입력은 화면에만, 저장 안 함 또는 로컬만)
/:level/lesson/:n         차시 학습 페이지 (아래 6장)
/:level/lab               프롬프트 실험실 (아래 7장) — 이 사이트의 핵심
/:level/cards             바로 쓰는 말 카드 / 요청문 카드 (복사 버튼)
/:level/glossary          낱말 사전 / 개념 사전 (차시 번호 연결)
/:level/project           13차시 종합 프로젝트 워크시트 (7단계, 내보내기)
/teacher                  교사 안내: 지도 원칙, 차시별 흐름·발문·예시 답·지도 팁, 평가 계획 (교사용 지도서 내용)
/about                    원저작·교재 출처, 이용 안내, 개인정보 안내
```

- URL 구조는 `level = elementary | middle | high`.
- 상단에 학교급 전환 버튼, 차시 안에서는 '이전/다음 차시'와 진행 표시.
- **수업 모드** 토글: 전자칠판용으로 글자를 키우고 한 화면에 한 블록씩 넘기는 발표 보기.

## 6. 차시 학습 페이지 구성

교재의 한 차시 짜임을 그대로 따른다. 블록 단위 컴포넌트로 만들고, 콘텐츠 JSON의 순서대로 렌더링한다.

| 순서 | 블록 | 화면 동작 |
|---|---|---|
| 1 | 이번 시간에 배울 것 | 목표 2~3개 |
| 2 | 생각 열기 | 질문 + 짧은 메모 칸(로컬 저장) |
| 3 | 이야기 | 채팅 말풍선 형태로 장면별 넘기기 (학생 ↔ AI). 장면마다 '낱말' 팝업 |
| 4 | 알아보기 · 오늘의 낱말 | 설명 + 낱말 카드 |
| 5 | 생활 속 비유 | 그림 카드(모델하우스, 마네킹 옷, 길 묻기, 미용실, 게임 세이브, 담임 인수인계 등) |
| 6 | 꼭 기억해요 | 핵심 문장 강조 박스 |
| 7 | 활동 1~3 | 아래 '활동 컴포넌트' 중 해당 유형으로 |
| 8 | AI 역할 놀이 (초·중) | 짝 활동 안내 카드 + 타이머 |
| 9 | 스스로 점검해요 | 체크리스트 |
| 10 | 오늘의 한 문장 | 큰 카드 + 복사 버튼 + "실험실에서 써 보기" 버튼 |
| 11 | 생각 노트 | 자유 메모(로컬 저장) |

### 6-1. 활동 컴포넌트 (재사용 단위로 만든다)

| 컴포넌트 | 쓰는 곳(예) | 설명 |
|---|---|---|
| `MatchPairs` 낱말 잇기 | 1차시 | 낱말 ↔ 뜻 연결, 즉시 피드백 |
| `CompareTable` 원한 것 vs 만든 것 ○/× | 2차시 | 표에서 ○/× 고르기 |
| `RewriteVague` 막연한 부탁 고치기 | 3차시 | "더 잘해 줘" → 구체적 부탁으로 바꿔 쓰기 + 규칙 기반 피드백 |
| `SortExtras` 덧붙임 분류 | 4차시 | AI 답의 문장을 '부탁한 것 / 덧붙인 것 / 도움 된 덧붙임 / 일을 키운 덧붙임'으로 끌어다 놓기 |
| `RestateCheck` 되말하기 판별 | 5차시 | 되말하기 vs 따라 말하기 구분, 모호한 말의 여러 해석 고르기 |
| `FourLines` 네 줄(네 칸) 만들기 | 6, 13차시 | 문제·기준·경계·완료 조건 입력 → 요청 문장 자동 조립 |
| `VerifyTable` 검증 표 | 7, 13차시 | 확인할 사실 / 확인한 곳 / 결과(맞음·틀림·확인 못 함) |
| `MisVsDiff` 오해 vs 의견 차이 | 8차시 | 사례 카드를 두 칸으로 분류 |
| `HonestyChecklist` 정직한 AI 사용 | 9차시 | 체크리스트 + 'AI 활용 안내 문장' 만들기 |
| `ReasonTags` 이유 이름표 | 10차시 | 문장마다 확인된 사실 / 제약 / 선호·가치 / 경험 / 추론(짐작) / 모르는 것 중 고르기 (정답 하나를 고집하지 않음 — 교사용 지도 팁 반영) |
| `ChoiceRecord` 다섯 줄 선택 기록 | 10차시 | 고른 것·이유·뺀 후보·불확실한 점·다시 볼 조건 |
| `RestartSix` 재시작 여섯 줄 | 11차시 | 6항목 입력 → **새 대화에 붙여 넣을 문장으로 변환·복사** |
| `CloseFive` 마무리 다섯 질문 | 12, 13차시 | 처음 문제 / 완료 조건 충족 / 충분한가 / 남은 차이·위험 / 다시 열 조건 |
| `ProjectSteps` 종합 프로젝트 7단계 | 13차시 | 위 컴포넌트들을 순서대로 묶은 워크시트 + 자기·친구 평가표 + 인쇄/PDF 내보내기 |

## 7. 프롬프트 실험실 (핵심 기능)

AI 계정 없이 '부탁 → 첫 결과물 → 되말하기 → 바로잡기 → 마무리' 한 바퀴를 경험하게 하는 **시뮬레이션**이다.
실제 AI가 아니라 **미리 써 둔 응답 + 규칙 기반 피드백**으로 동작한다. (이유: 초등은 이용 연령 문제로 실제 AI 사용 불가, 비용·개인정보 위험 없음, 교재 예시와 정확히 일치)

### 7-1. 흐름

1. **시나리오 고르기** — 학교급별 3~5개. 처음엔 교재 이야기 그대로:
   - 초등: 학급 신문(우리 학교 운동회 소식), 생일 초대장, 가족 소풍 계획
   - 중학: 부산 기후 3분 발표, 친구 선물 키링 고르기
   - 고등: 진로 연계 탐구 보고서(유전자 편집 작물 인식), 동아리 박람회 15분 발표, 동아리 출결 앱 MVP
   - 각 시나리오에는 **학생에게만 보이는 '숨은 조건'** 카드가 있다 (예: "간단하게 = 행정 용어 없이", "동아리별 상세 소개는 제외").
2. **부탁 쓰기** — 학생이 프롬프트를 쓴다.
3. **즉시 점검** (규칙 기반, 아래 7-2)
4. **첫 결과물 보기** — 프롬프트에 담긴 요소 수에 따라 미리 써 둔 응답 중 하나를 보여 준다.
   - 요소 거의 없음 → 그럴듯하지만 엉뚱하고 덧붙임이 많은 답 (예: 다른 학교 소식, 없는 수영장)
   - 일부 포함 → 일부만 맞는 답
   - 네 줄 모두 포함 → 숨은 조건에 맞는 답
5. **점검 버튼** — "원한 것과 다른 곳 찾기": 결과물의 문장을 눌러 '틀림/덧붙임/확인 필요'로 표시. 숨겨 둔 정답과 비교해 피드백.
6. **되말하기 요청 버튼** — 누르면 시뮬레이션 AI가 "이렇게 이해했습니다"를 보여 준다. 학생은 맞는 부분/어긋난 부분을 고르고 바로잡는 문장을 쓴다.
7. **바로잡은 결과물** → 검증 표(사실·숫자 확인) → 추가 제안 받을지 결정(판단권) → 선택 기록 → 마무리 다섯 질문
8. **나의 기록 내보내기** — 이번 실습의 네 줄·되말하기·검증·선택 기록·재시작 여섯 줄을 한 장으로 인쇄 또는 텍스트 복사.

### 7-2. 규칙 기반 피드백 (규칙은 `content/rules/*.json`으로 분리해 교사가 고칠 수 있게)

| 점검 | 방법 | 피드백 예(초등 말투) |
|---|---|---|
| 막연한 말 | 사전 목록: 간단하게, 짧게, 잘, 좋게, 예쁘게, 자세히, 쉽게, 고등학생 수준, 적당히 … | "'짧게'는 사람마다 뜻이 달라요. 몇 줄인지 숫자로 말해 볼까요?" |
| 네 줄 요소 | 문제/목적, 기준(가장 중요한 것), 경계(빼 줘·넣지 마), 완료 조건(몇 줄·몇 분·무엇이 들어가면) — 키워드·패턴으로 감지 | 빠진 칸만 알려 주고, 네 칸 카드로 바로 보충할 수 있게 |
| 범위 분리 | "추가 제안", "따로", "맨 아래" 등 | "좋은 생각은 따로 받자고 말해 두면 헷갈리지 않아요." |
| 되말하기 요청 | "어떻게 이해했는지", "먼저 말해/설명해" | 포함 시 칭찬 배지 |
| 검증 요청 | "확인해야 할", "출처", "확실하지 않은 것 표시" | 7차시 이후 시나리오에서 점검 |
| **개인정보** | 이름 패턴(○○초/중/고, ○학년 ○반), 전화번호, 주소, 이메일 정규식 | 입력 즉시 경고: "이름·학교·연락처는 AI에게 말하지 않아요." (저장·전송하지 않음) |

- 피드백은 **점수 대신 "잘한 점 1개 + 더 해 볼 것 1개"** 형식. 고칠 곳 찾기는 실패가 아니라는 교재 메시지를 지킨다.
- 규칙은 완벽할 수 없으므로 화면에 "이 점검은 도우미일 뿐, 판단은 내가 해요" 안내를 둔다.

### 7-3. 실제 AI로 해 보기 (중·고만, 기본 숨김)

- 교사 설정에서 켤 때만 "내 부탁 복사하고 AI 열기" 버튼 표시 → 클립보드 복사 후 외부 AI 서비스 새 탭.
- 버튼 옆에 고정 안내: 이용 연령·보호자 동의, 학교 지침, 개인정보 입력 금지.
- 사이트가 직접 AI API를 부르는 기능은 이번 범위에서 **만들지 않는다** (9장 4단계에서 별도 판단).

## 9. 단계별 진행 (MVP부터 — 각 단계 끝에 멈추고 확인받는다)

### 1단계 — 뼈대 + 중학교 1~6차시 + 실험실 시나리오 1개
- 공통 레이아웃, 학교급 선택, 차시 페이지 블록 렌더러
- 중학교 1~6차시 콘텐츠 이관 (워크북 + 교사용 지도서)
- 활동 컴포넌트: MatchPairs, CompareTable, RewriteVague, SortExtras, RestateCheck, FourLines
- 실험실: 중학 '부산 기후 3분 발표' 시나리오 1개, 규칙 점검(막연한 말·네 줄·범위 분리·되말하기·개인정보)
- **완료 조건**: 휴대폰과 PC에서 1~6차시를 끝까지 넘길 수 있고, 실험실에서 부탁 → 첫 결과물 → 되말하기 → 바로잡기까지 한 바퀴가 돈다. 개인정보 경고가 뜬다.

### 2단계 — 세 학교급 13차시 전부
- 초등·고등 콘텐츠 이관, 중학 7~13차시
- 나머지 활동 컴포넌트, 낱말/개념 사전, 말 카드, 약속/협업 원칙, 종합 프로젝트 워크시트 + 인쇄
- 실험실 시나리오 학교급별 최소 2개
- **완료 조건**: 39개 차시가 모두 열리고, 차시마다 '오늘의 한 문장'이 4-1 표와 일치. 13차시 워크시트가 A4 인쇄로 깔끔히 나온다.

### 3단계 — 교사 기능
- `/teacher`: 지도 원칙, 차시별 수업 흐름·발문·예시 답·지도 팁·FAQ, 평가 계획·채점 기준
- 수업 모드(전자칠판 발표 보기), '실제 AI로 해 보기' 버튼 켜기/끄기(로컬 설정)
- **완료 조건**: 교사가 지도서 없이 화면만으로 한 차시를 진행할 수 있다.

### 4단계 — (선택, 별도 결정 후) 확장
- 학급 코드로 결과물 모아 보기(Firebase), 실제 AI 연결(서버 함수로 키 보호, 중·고·교사 승인 시만) 등
- 이 단계는 **1~3단계를 실제 수업에 써 본 뒤** 필요할 때만 착수한다.

## 10. 콘텐츠 이관 방법

1. `source/`의 PDF에서 텍스트를 뽑는다 (`pdftotext -layout`). 쉽게 풀어 읽기 본은 원문 해설·비유·용어 정리의 기준으로 쓴다.
2. 차시별 JSON을 만든다. **교재 문장을 고쳐 쓰지 말고 그대로 옮긴다.** 줄바꿈으로 깨진 띄어쓰기(예: "추 가 제안")만 바로잡는다.
3. PDF의 그림(인물, 비유 그림)은 그대로 쓰지 말고 간단한 일러스트/아이콘으로 대체한다 — 사용 허락이 확인되면 교체.
4. 옮긴 뒤 차시마다 `원문 대조: 완료/미완료`를 `docs/PROGRESS.md`에 표로 남긴다.

## 11. 하지 않을 것 (경계)

- 회원가입·로그인·학생 이름 수집 (서약 화면의 이름도 저장하지 않거나 로컬에만)
- 학생 입력을 서버로 보내는 기능, 분석 도구(GA 등) 삽입
- 점수·순위·경쟁 요소 (교재는 "정답보다 과정을 칭찬"을 원칙으로 함)
- AI를 "믿으면 안 되는 것"으로 그리는 문구 — "AI는 짐작을 하니, 우리가 확인해야 한다"는 관점을 유지
- 교재에 없는 새 개념이나 예시를 임의로 만들어 넣기 (필요하면 `추가제안.md`로)
- 1~3단계에서 AI API 호출
