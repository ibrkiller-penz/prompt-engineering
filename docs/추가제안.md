# 추가 제안 (범위 밖 — 코드에 넣지 않음)

각 제안이 작업 시간·복잡도에 주는 영향을 함께 적었다. 넣을지는 사용자가 정한다.

| # | 제안 | 기대 효과 | 작업 시간 | 복잡도 |
|---|---|---|---|---|
| A1 | 전자칠판 화면에 QR 코드 띄우기 (학생 기기에서 같은 차시 바로 열기) | 수업 시작이 빨라짐 | 약 30분 | 낮음 (QR 라이브러리 1개) |
| A2 | 오프라인 사용(PWA) | 학교 와이파이가 불안정해도 열림 | 1~2시간 | 중간 (캐시 갱신 관리) |
| A3 | 실험실 응답을 요소 조합별로 조립 (예: "빼 줘"라고 썼으면 해당 슬라이드 빠짐) | D6의 어색함 해소, 더 실감 나는 피드백 | 시나리오당 2~3시간 | 중간~높음 (시나리오 JSON 형식 확장) |
| A4 | 바로잡는 말에 빠진 조건이 있으면 두 번째 결과물도 일부만 맞게 | "한 번 고치면 끝"이 아니라는 메시지 강화 | 시나리오당 1시간 | 중간 |
| A5 | 교사용 "JSON 고치는 법" 안내서 (`docs/콘텐츠수정안내.md`) | 교사가 직접 문장·규칙 수정 | 1시간 | 낮음 (문서만) |
| A6 | 차시 안 '낱말' 팝업을 본문 낱말에 밑줄로 연결 | 이야기를 읽다 바로 뜻 확인 | 2시간 | 중간 |
| A7 | 허브(첫 화면)에 꼭지 검색·분류 | 자료가 많아지면 찾기 쉬움 | 1~2시간 | 낮음 |
