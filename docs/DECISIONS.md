# 선택 기록 (DECISIONS)

각 항목은 다섯 줄: ① 고른 것 ② 고른 이유(사실/제약/추론 표시) ③ 고르지 않은 대안 ④ 불확실한 점 ⑤ 재검토 조건

## D1. 사이트 구조 — 교육자료 허브 + `/prompt` 꼭지
① `penedu.web.app` 첫 화면은 "살빠진 임선생과 함께하는 교육자료" 허브, 다시 묻는 AI 교실은 `/prompt` 아래 꼭지로 둔다.
② [사실] 사용자가 "pen 사이트에 한 꼭지로 넣고 나중에 교육자료를 추가"하기로 정함. [추론] 꼭지별 경로로 나누면 새 자료를 `src/site.ts`의 `SECTIONS` 한 줄 + 라우트로 더할 수 있다.
③ 꼭지마다 별도 Firebase 사이트(주소 여러 개), 별도 저장소.
④ 꼭지가 많아지면 한 번들이 커질 수 있음.
⑤ 꼭지가 3개를 넘거나 번들이 500KB(gzip)를 넘으면 꼭지별 지연 로딩(lazy import)으로 나눈다.

## D2. 배포 주소 — `penedu.web.app` (Firebase 프로젝트 `firsttest-5db1f` 안의 Hosting 사이트)
① 기존 프로젝트 `firsttest-5db1f`에 Hosting 사이트 `penedu`를 추가해 배포.
② [사실] 계정의 Google Cloud 프로젝트 생성 한도 초과로 새 프로젝트를 만들 수 없음. `pen`은 다른 사람이 사용 중. 사용자가 `penedu`를 고름.
③ 새 Firebase 프로젝트(한도로 불가), GitHub Pages.
④ 프로젝트 이름이 `firsttest`라 콘솔에서 찾기 헷갈릴 수 있음.
⑤ 4단계에서 Firestore 등 서버 기능을 쓰게 되면 전용 프로젝트로 옮길지 다시 본다.

## D3. 콘텐츠 위치 — `content/prompt/...` 정적 JSON
① 지시서의 `content/{level}/lesson-01.json` 대신 `content/prompt/{level}/lesson-01.json`, `content/prompt/lab/{level}/*.json`, `content/prompt/rules/*.json`.
② [추론] 허브 구조(D1)에서 다른 꼭지 콘텐츠와 섞이지 않게 꼭지 이름 폴더를 한 단계 둔다. 형식은 지시서 8-1을 따르되 블록 종류를 몇 개 더함(`promise` 약속, `explain`의 `table`/`dialogue`/`steps`/`after`).
③ 지시서 경로 그대로.
④ 교사가 JSON을 직접 고칠 때 형식 안내가 필요함 → `src/content/types.ts`가 기준.
⑤ 교사용 편집 화면을 만들게 되면 다시 본다.

## D4. 기술 버전 — Vite 8 + React 19 + TypeScript 7 + Tailwind 4 + React Router 7
① 지시서 기본안 그대로, 설치 시점 최신 버전.
② [사실] 2026-10 기준 최신 안정판. Tailwind 4는 `@tailwindcss/vite` 플러그인과 CSS `@theme` 방식.
③ Next.js 등(정적 사이트에 과함).
④ TypeScript 7(네이티브 컴파일러)은 새 버전이라 도구 호환이 덜 검증됨.
⑤ 빌드·타입 검사에서 이상이 생기면 TypeScript 5.x로 내린다.

## D5. 활동 상호작용 — 끌어다 놓기 대신 버튼 고르기
① 낱말 잇기·덧붙임 분류·○/× 모두 "누르기"로만 동작(끌어다 놓기 없음).
② [제약] 지시서: 끌어다 놓기 활동은 버튼 대안 필수, 터치 44px. [추론] 버튼만 쓰면 휴대폰·전자칠판·키보드에서 한 가지 방식으로 다 된다.
③ 끌어다 놓기 + 버튼 대안 두 가지 제공.
④ 전자칠판에서 끌어다 놓기가 더 재미있을 수 있음.
⑤ 실제 수업 후 학생 반응을 보고 다시 본다.

## D6. 실험실 응답 선택 — 네 줄 요소 개수(0~4)로 응답 3종 중 하나
① 요소 4개 → `good`, 2~3개 → `partial`, 0~1개 → `plain` (시나리오 JSON `pick`).
② [제약] 지시서 7-1 "요소 수에 따라 미리 써 둔 응답 중 하나". 
③ 요소 조합마다 다른 응답(조합 16가지).
④ 학생이 "해결 방법은 빼 줘"라고 써도 `partial` 응답에 해결 방법이 들어가는 어색함이 있을 수 있음. 바로잡은 뒤에는 항상 `good`이 나옴.
⑤ 수업에서 어색하다는 반응이 있으면 `추가제안.md` A3(조건별 응답 조립)로 넘어간다.

## D7. 5차시 '되말하기 골라내기' 연습 추가
① 5차시에 교재 문장만으로 구성한 `RestateCheck` 연습 블록("연습")을 활동 1~3 앞에 둔다.
② [제약] 지시서 6-1이 5차시에 `RestateCheck`를 지정. 워크북 5차시 활동 1~3은 모두 쓰기 활동이라 해당 컴포넌트가 들어갈 자리가 없음.
③ RestateCheck 생략.
④ 교재에 없는 활동 형식이므로 교사 검토가 필요함(문장은 모두 교재의 것).
⑤ 교사가 빼자고 하면 JSON에서 블록 하나를 지우면 된다.

## D8. 교재 옮기기 — 보조 에이전트 6개 병렬 + 형식 문서
① `docs/콘텐츠형식.md`를 먼저 쓰고, 학교급·차시 범위별로 6개 에이전트가 동시에 JSON으로 옮김. 마지막에 전체를 자동 점검(39차시·한 문장 36개·컴포넌트 이름·TODO).
② [제약] 33차시+부록+시나리오 분량. [추론] 형식을 문서로 고정하면 병렬 작업 결과가 한 모양으로 모인다.
③ 한 차시씩 직접 옮기기(시간 3~4배).
④ 에이전트마다 판단이 조금씩 다름(아이콘·노트 블록 등) — 보고서를 받아 정리함.
⑤ 교사가 원문과 다른 곳을 찾으면 그 차시 JSON만 고친다.

## D9. 활동지 PDF — 사회 학습실(social-study) 방식
① A4 인쇄용 화면(`/prompt/print?level&l&p`) + 「활동지 PDF 받기」 창(골라서 인쇄용 화면 열기 / 미리 만든 PDF 바로 받기) + `scripts/make-pdfs.mjs`(Edge로 인쇄용 화면을 PDF로 저장, `public/pdf/prompt/`).
② [사실] 사용자가 사회과목 사이트 방식을 지정. [추론] 화면용 컴포넌트와 같은 JSON에서 종이용 렌더러(PrintBlocks)를 따로 그리면 콘텐츠를 한 번만 고치면 된다.
③ PDF 라이브러리로 직접 그리기(jsPDF 등) — 한글 글꼴·표 처리가 번거로움.
④ PDF 45개(약 30MB)가 저장소와 배포에 함께 올라감.
⑤ 용량이 문제 되면 PDF를 Firebase Storage로 옮기거나 '전체' 파일만 미리 만든다.

## D10. 차시를 여는 이야기 + Canva 삽화
① 각 차시 맨 위(그리고 활동지 PDF의 첫 쪽)에 수필 『다 된 줄 알았다』의 해당 장을 A4 한 쪽 분량으로 줄인 이야기와 Canva 삽화 1장(`content/prompt/stories/lesson-NN.json`, `public/img/prompt/*.webp`). 같은 차시 번호는 같은 장면, 문체는 학교급별(초: "선생님은 …했어요" 쉬운 해요체 / 중: 1인칭 해요체 / 고: 수필 원래 반말 문체). 첫 페이지는 깔끔하게 둠.
② [사실] 사용자 요청: "메인이 아니라 각 차시별로 스토리를, 메인은 깔끔하게", "초중고 수준에 맞춰 문체 재구성", "삽화는 캔바에서 밝고 교육적으로". [사실] 교재 13차시가 원문 장 순서(서문→1장…10장)를 따르므로 수필 장과 짝이 맞음.
③ 첫 페이지에 한 편만 두기(처음 안), 학교급마다 다른 장면.
④ 줄이고 문체를 바꾼 문안은 사용자 검토 필요. 같은 장(1장·4장)을 두 차시가 나눠 씀.
⑤ 학교급별로 다른 장면이 필요하면 `levels` 아래에 `image`를 따로 둔다.

## D11. 생각 노트는 모든 차시에
① 교재에 ‘나의 생각 노트’ 쪽이 없는 차시도 노트 블록을 넣음.
② [사실] 사용자: "원문은 참고하고, 생각노트는 다 넣자". [추론] 모든 차시가 같은 짜임으로 끝나면 학생이 덜 헷갈린다.
③ 원문에 있는 차시만(초 4·8·10~13, 중 2~5·7~9·13, 고 1·3~5·7·9~13).
④ 없음.
⑤ 원문과 똑같이 맞춰야 하는 요청이 오면 위 목록대로 되돌린다.

## D12. 6번째 꼭지 `/board` — ESP32 터치 화면 시간표 단말 만들기 (2026-10-06)
① 허브 맨 끝에 `/board` 꼭지를 더하고, 쪽 8개(시작·준비물·PC 준비·처음 굽기·내 시간표·화면 흔들림·막힐 때·AI 작업지시서)로 나눈다. 7인치(Waveshare ESP32-S3-Touch-LCD-7)가 중심, 4인치(V4.0)는 서브.
② [사실] 사용자 지시: 개발보드·개발보드2 작업을 6번째 꼭지로, 시간표 개인정보 제거, 다른 선생님이 보드를 사서 따라 할 수 있게, 화면 흔들림 설명 필수, 작업지시서까지. 시작 프로젝트는 `board-kit/`(common·7inch·4inch)에서 `scripts/make-board-zips.py`로 `public/board/*.zip`을 만든다. 학교·교사·학교 코드·프로젝트 ID는 모두 뺐다.
③ 꼭지 하나에 긴 글 한 쪽, 설명서만(키트 없이).
④ 화면 흔들림 마지막 설정(2026-10-02)은 켜기·받기·터치 정상 확인, 밀림 재발 여부는 지켜보는 중 — `Shake.tsx`에 날짜와 함께 적어 둠. 7인치 보드는 5인치 데모 설정에서 시작했고 핀 표가 7인치 설명서와 같음을 확인(키트 검증 보고 참고).
⑤ 지켜본 결과가 나오면 `Shake.tsx`의 ‘아직 지켜보는 중’ 상자를 고친다.
